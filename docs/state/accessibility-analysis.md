# Accessibility analysis

Reviewed against `.claude/rules/accessibility-ruleset.md` (WCAG 2.2 AA / Brickfield Checker v2.0).
Scope: all PHP files that emit HTML — [badgeawarder.php](../../badgeawarder.php), [tracker.php](../../tracker.php),
[processor.php](../../processor.php), [block_badgeawarder.php](../../block_badgeawarder.php),
[forms/step1_form.php](../../forms/step1_form.php), [forms/step2_form.php](../../forms/step2_form.php),
[locallib.php](../../locallib.php), [settings.php](../../settings.php), and the strings that get
rendered into HTML/email from [lang/en/block_badgeawarder.php](../../lang/en/block_badgeawarder.php).

| Severity | File | Line | Problem | Recommended fix | Outcome |
|----------|------|------|---------|-----------------|---------|
| Critical | tracker.php | 129-130 | The results `<table>` is given a `summary` attribute only (`'summary' => get_string('awardresulttablesummary', ...)`). `summary` is an obsolete HTML4-only attribute with no accessible-name effect in HTML5, and the table has no `<caption>`. Fails "Data tables: `<caption>` required." | Replace the `summary` attribute with a real `<caption>` element (`html_writer::tag('caption', get_string('awardresulttablesummary', 'block_badgeawarder'))`) as the table's first child, before the header row. | **Fixed** — `start()` now drops the `summary` attribute and emits `html_writer::tag('caption', ...)` immediately after the opening `<table>` tag. |
| Critical | tracker.php | 106-110 | `output()` renders the pass/fail outcome for each CSV row purely as `$OUTPUT->pix_icon('i/valid', '')` / `pix_icon('i/invalid', '')` — the alt text is an empty string. The "Result" column's only content is this icon, so its meaning (success/failure) is conveyed by the icon alone with no accessible name. Fails WCAG 1.1.1 and "Information must not be conveyed by colour/icon alone." | Give the icon a real, localised alt string, e.g. add `$string['iconsuccess'] = 'Success';` / `$string['iconerror'] = 'Error';` to lang/en/block_badgeawarder.php and pass `get_string('iconsuccess', 'block_badgeawarder')` / `get_string('iconerror', 'block_badgeawarder')` as the icon's alt argument instead of `''`. | **Fixed** — added the two lang strings and pass them as the second argument to `pix_icon()` in `output()`. |
| Moderate | processor.php | 572 | `preview()` echoes `html_writer::tag('h3', get_string('preview', ...) . ' ' . $choices[$this->mode])` directly onto the preview page. The page heading set via `$PAGE->set_heading()` in `block_badgeawarder_page_header()` (locallib.php:36) renders as the page's `<h1>`, so this `<h3>` skips `<h2>`. Fails "No skipped heading levels." | Change the tag to `'h2'` so the preview heading sits directly under the page's `<h1>`, or introduce an intermediate `<h2>` section heading before it. | **Fixed** — changed the tag from `h3` to `h2`. |
| Moderate | tracker.php | 103-105 | When a row has more than one status message, `output()` joins them with `html_writer::empty_tag('br')` inside a single `<td>` (e.g. "Missing required fields<br>Badge does not exist"). Multiple discrete reasons rendered as `<br>`-separated text is a fake list. Fails "No fake lists (bullet symbols, `<br>`-separated, CSS-only bullets on `<p>`)." | Wrap multi-message status cells in a real list, e.g. `html_writer::alist($status)` (produces a `<ul><li>` per message) instead of `implode(html_writer::empty_tag('br'), $status)`, when `$status` has more than one entry. | **Fixed** — `output()` now renders `html_writer::alist($status)` when there's more than one message, and the single message unwrapped otherwise (avoids a one-item `<ul>` for the common case). |
| Low | lang/en/block_badgeawarder.php | 54-61 | `emailawardtextnew` renders the new account's username and password as a `<br>`-separated block (`username: {$a->username}<br>   password: {$a->newpassword}<br>`) rather than a real list, in the HTML email sent to newly created users. Fails "No fake lists" (applies to any generated HTML, including email bodies). | Mark up the two credential lines as a real list, e.g. `<ul><li>Username: {$a->username}</li><li>Password: {$a->newpassword}</li></ul>`, so email clients that render as HTML expose it as a proper list rather than plain `<br>`-joined text. | **Fixed** — replaced the two `<br>`-joined credential lines with a `<ul><li>...</li></ul>` list. |
